# 稳定轨迹承诺区间设计

## 背景

最新运行 `20260723_093459` 的 93 次规划中，首次轨迹初始化后，后续 92
个模型候选全部被接纳。执行轨迹终点相邻更新的平均跳变为 `1.456 m`，最大
跳变为 `5.593 m`。当前 `TrajectoryManager` 只把候选首点投影到历史轨迹，
候选首点又通常位于底盘附近，因此每轮只保留很短的历史前缀，远端轨迹几乎
被整体替换。

BEV 还存在一个次要时序问题：RGB-D 点云来自 `FrameSnapshot`，轨迹坐标
转换却使用视频线程执行时的最新里程计。线程延迟会让点云与轨迹对应不同底盘
时刻。

## 目标

- MPC 轨迹继续从当前底盘位置开始。
- 底盘前方默认 `1.0 m` 的历史轨迹成为稳定承诺区间，新候选不能改写。
- 新候选必须与历史轨迹连续重叠一段距离，不能凭单个交叉点接入。
- 在有效重叠点之后仍允许更新和延长远端轨迹。
- RGB-D 点云和黄色引导点使用同一帧对应的底盘位姿。
- 模型请求失败、低 critic 或候选不连续时继续执行可用历史轨迹。

## 方案比较

### 方案 A：承诺区间加连续重叠，采用

锁定底盘前方一段历史轨迹，在锁定区间之后寻找候选与历史的最远连续重叠点。
该方案让即将执行的近场路径稳定，同时保留远端重规划能力。

### 方案 B：历史和候选数值平滑

对两个轨迹加权平均可以让画面平滑，但平均路径不一定满足模型输出、历史路径
或障碍物约束，因此不采用。

### 方案 C：历史轨迹耗尽前完全拒绝候选

稳定性最高，但无法及时响应新障碍或纠正远端路线，且轨迹延长发生得太晚，
因此不采用。

## TrajectoryManager 接缝规则

保留现有的轨迹前推、底盘重锚定、`0.05 m` 重采样、接缝距离和接缝方向
检查。在此基础上增加：

- `commit_horizon = 1.0 m`：候选接缝在历史轨迹上的累计弧长不得小于该值。
- `overlap_length = 0.5 m`：接缝前至少检查候选的这段连续轨迹。
- `overlap_distance = 0.30 m`：重叠窗口内候选采样点到历史轨迹的最大距离
  不得超过该值。

每轮先把候选按 `point_spacing` 重采样。对候选点逐个投影到历史轨迹，并
计算历史投影弧长。一个接缝只有同时满足以下条件才有效：

1. 历史投影弧长位于承诺区间之后；
2. 候选在接缝前具有至少 `overlap_length` 的可检查轨迹；
3. 重叠窗口内每个候选采样点到历史轨迹的距离不超过
   `overlap_distance`；
4. 重叠窗口内各点投影到历史轨迹的累计弧长单调不减，避免回环或孤立交叉
   被误认为连续重叠；
5. 接缝空间距离不超过现有 `join_distance`；
6. 接缝后至少保留一个候选线段，且历史方向、连接方向和候选后续方向满足
   现有 `join_heading`。

如果存在多个有效接缝，选择历史弧长最大的接缝。这样会尽量保留历史，只用
候选更新尚未承诺的远端尾部。候选与历史只有孤立交叉点时，连续重叠检查会
拒绝接入。

当历史剩余长度不足 `commit_horizon + min_remaining` 时，实际承诺长度缩短
为：

```text
max(0, history_remaining - min_remaining)
```

这让短历史仍能在耗尽前通过连续重叠候选得到延长。首次没有历史轨迹时仍从
底盘到候选线性补点，不应用承诺区间。

没有有效接缝时保留历史，并通过原因区分承诺区间不足、连续重叠不足、距离
不连续和方向不连续。诊断记录增加实际保留弧长与重叠最大误差，便于现场验证。

## BEV 时序

`_render_mpc_bev` 使用 `snapshot.odom_xy_yaw` 将 `odom` 坐标系的
`active_traj` 和 MPC 预测轨迹转换到当前 RGB-D 帧的底盘坐标系。最新
里程计时间仍用于判断 ODOM 是否新鲜；快照本身没有里程计时不绘制这些轨迹。

该改动只修正可视化对齐，不改变 MPC 求解使用的实时里程计。

## 参数

客户端新增以下参数并使用上述默认值：

```text
--trajectory-commit-horizon 1.0
--trajectory-overlap-length 0.5
--trajectory-overlap-distance 0.30
```

所有参数必须为有限正数。现有 `join_distance`、`join_heading`、
`point_spacing` 和 `min_remaining` 参数保持兼容。

## 测试

TrajectoryManager 单元测试覆盖：

- 近场开始相同但远端左右摆动的连续候选不能改变前 `1.0 m` 历史；
- 候选与历史只有孤立交叉点时被拒绝；
- 连续重叠超过承诺区间的候选在最远有效重叠点之后更新远端；
- 历史较短时可以缩短承诺区间并安全延长；
- 首次初始化、低 critic、历史耗尽和原有距离/方向边界不回归；
- 诊断中的保留长度和重叠误差与实际接缝一致。

客户端源码测试覆盖新参数默认值、参数传递、诊断字段，以及 BEV 使用
`snapshot.odom_xy_yaw` 而不是渲染时最新位姿。最终运行完整相关测试和静态
检查。
