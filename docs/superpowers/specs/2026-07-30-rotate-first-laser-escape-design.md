# Laser 起点碰撞原地转向逃逸设计

## 背景

当前 Laser 轨迹调整器在碰撞从密集轨迹第 0 点开始时无法构造“碰撞前渐变”，
因此直接返回 `adjustment_unsafe`。规划线程随即清空活动轨迹，控制线程进入
`trajectory_missing` 并停车。

`20260730_072537_mpc.jsonl` 证明这会产生误停：持续停车开始时，轨迹首点离
最近障碍物约 `0.317 m`，略低于 `0.32 m` 路径安全半径；但机器人中心离该
障碍物约 `0.344 m`，当前位置仍然安全。差速底盘允许 `v=0、w!=0`，可以先
原地转向安全侧，再沿逃逸轨迹前进。

## 目标

- 起点附近阻挡但机器人当前位置安全时，不再直接停车。
- 生成从机器人当前位置连续出发、绕向安全侧的 Laser 调整 guide。
- 航向未对齐时强制线速度为零，使用 MPC 角速度原地转向。
- 对齐后恢复现有 MPC 跟踪，不增加独立避障控制器。
- 雷达失效、当前位置不安全或左右确实均无逃逸路线时仍然停车。

## 非目标

- 不修改 NavDP 模型、critic 评分或候选轨迹选择。
- 不实现全局规划、倒车恢复或多阶段避障状态机。
- 不改变“绕开障碍后保持偏移，由后续 diffusion 自然拉回”的既有策略。
- 不降低全局 `0.32 m` 路径安全半径。

## 设计

### 1. 起点碰撞分类

调整器继续先对密集 diffusion 轨迹计算 `0.32 m` 碰撞掩码。

- 没有碰撞：轨迹原样通过。
- 首个碰撞点不在轨迹起点：继续使用现有平滑侧向调整。
- 碰撞从轨迹起点开始：
  - 先检查机器人局部原点 `[0, 0]` 到当前障碍物的最小距离。
  - 原点距离小于 `0.32 m` 时，原地旋转本身也不满足当前圆形安全模型，
    返回不安全并停车。
  - 原点安全时，进入 `rotate_first` 逃逸轨迹生成。

### 2. 原点锚定逃逸 guide

逃逸 guide 复用现有轨迹法向、左右侧候选、偏移步长和最大偏移参数，不另写
一套轨迹插密算法。

每个候选满足以下条件：

1. 以机器人当前位置 `[0, 0]` 为第一个 guide 点。
2. 将起始受阻 waypoint 推向候选侧，偏移量使用现有障碍净空搜索得到的最小
   安全偏移。
3. 后续 waypoint 使用现有单侧、单调偏移包络；绕过障碍后保持偏移，不在
   当前帧回归原始轨迹。
4. 对原点到调整后首段以及后续完整 guide 做离散净空复核。
5. 原点锚点保持机器人当前净空，原点之后的所有离散样本都必须达到
   `0.32 m` 净空。

左右均可行时，沿用现有规则选择安全且最大偏移更小的一侧。左右均不可行时
才返回 `adjustment_unsafe`。

调整结果增加：

- `rotate_first: bool`
- `initial_heading_local_rad: Optional[float]`

初始航向取原点锚定逃逸 guide 的第一个有效切向方向。

### 3. 控制行为

规划线程把局部初始航向转换为世界航向，并与活动轨迹同一代安装。轨迹失效
或 generation 变化时立即停止使用旧航向目标；若同一起点碰撞事件尚未结束，
事件的 `rotating` 或 `released` 相位继续锁存，新一代有效逃逸 guide 只能
继续该相位，不能把它重新初始化为一次新的原地转向。

`rotate_first` 不是通用的航向对齐功能。它只能替代以下一种原本会触发
`adjustment_unsafe` 强制停车的情况：

- 碰撞从轨迹第 0 点开始；
- 机器人局部原点满足 `0.32 m` 安全半径；
- 至少一侧能够生成通过净空复核的原点锚定逃逸 guide。

普通 guide 的航向误差无论多大，都不得启用 `rotate_first`。scan、odom、
frame、plan 过期，critic 不安全，到达目标，机器人原点不安全或左右无逃逸
路线等其他强制停车原因，仍然发布 `v=0、w=0`，不得用原地转向替代。

控制线程仍由现有 MPC 求解 `[v, w]`：

- 普通轨迹：原样使用 MPC 输出。
- 新的起点碰撞逃逸事件只进入一次 `rotate_first`。
- `rotate_first` 航向误差大于 `5°`：
  - 强制发布 `v=0`。
  - 保留 MPC 计算并限幅后的 `w`，使底盘原地转向 guide 方向。
- 航向误差进入 `5°` 以内：退出 `rotate_first`，恢复 MPC 线速度。
- 退出后，即使后续规划仍检测到同一段起点碰撞或航向误差再次增大，也不得
  在同一避障事件内重新进入 `rotate_first`。
- 起点碰撞连续 3 个规划周期消失后，认为本次避障事件结束并解除锁存；之后
  若再次出现满足上述条件的新强制停车事件，才允许重新启用一次。

现有 scan、odom、frame、plan 和轨迹 generation 安全门保持不变；任何安全门
失败仍立即发布零速度。

### 4. 可视化与诊断

- 黄色 `guide` 始终显示实际安装到 MPC 的 Laser 调整轨迹，包括原点锚定
  逃逸段。
- 青色 `selected` 继续显示 NavDP 原始轨迹。
- 控制日志在原地转向阶段记录 `control_mode=rotate_first`、目标航向和航向
  误差；安全停车 `reason` 的语义保持不变。
- 规划日志增加 `laser_rotate_first` 和 `laser_initial_heading_local_rad`。

## 测试

### 轨迹调整

- 使用 `20260730_072537` 首次持续误停的等价几何：原点净空大于 `0.32 m`、
  首 waypoint 净空略小于 `0.32 m`。结果必须安全、选择远离障碍物的一侧、
  guide 首点为原点并标记 `rotate_first`。
- 原点本身小于 `0.32 m` 时仍返回不安全。
- 左右两侧均被墙封死时仍返回不安全。
- 普通中段碰撞和无碰撞行为保持不变。

### 控制

- 普通轨迹即使航向误差大于 `10°`，也不得强制线速度为零。
- `rotate_first` 且航向未对齐时，线速度必须为零，角速度保留正确方向。
- 误差小于 `5°` 后恢复 MPC 线速度。
- 同一避障事件中误差重新增大时不得再次进入 `rotate_first`。
- 起点碰撞连续 3 个规划周期消失后，新的起点碰撞事件可以再次启用
  `rotate_first`。
- scan 过期、轨迹失效或 generation 变化但新 guide 尚未安装时，不得使用
  旧航向目标发布旋转命令。

### 回放验收

使用 `20260730_072537_mpc.jsonl` 中持续误停起始帧回放：

- 原 `adjustment_unsafe` 应变为安全的右侧 `rotate_first` guide。
- 起始控制命令为 `v=0、w<0`。
- 对齐后出现 `v>0`，且 guide 净空复核通过。

## 成功标准

- 当前误停样本不再进入 `trajectory_missing`，而是先原地向安全侧转向。
- `rotate_first` 每个起点碰撞避障事件最多启用一次，普通规划更新不会重复
  把线速度压到零。
- 真正无安全逃逸路线、机器人当前位置不安全或传感器失效时仍然停车。
- 不改变正常轨迹、既有中段避障和速度硬限幅行为。
