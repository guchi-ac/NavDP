# 近场历史引导点 TrajectoryManager 设计

## 背景

当前 `TrajectoryManager` 把第一条候选轨迹初始化为 `active_traj`，再通过
`1.0 m` 承诺区间和 `0.5 m` 连续重叠约束后续候选。该方案会让早期候选和
底盘到首个可见引导点之间的人工连接段长期影响执行轨迹。实际日志还显示，
连续重叠搜索使单次管理器更新耗时达到约 `0.8–1.4 s`，进而触发
`plan_stale` 停车。

D435 当前视角下，InternNav 最近的有效引导点通常距离底盘约 `1 m`。
TrajectoryManager 应利用车辆已经驶近的旧观测补足这段近场，而不是承诺一段
完整旧轨迹。

## 目标

- 只让历史引导点主导底盘前方 `1.0 m` 的近场。
- 最新合格候选直接更新近场以外的远场，不要求承诺区间或连续重叠。
- TrajectoryManager 不做数值融合或轨迹平滑；MPC 从当前底盘状态生成可执行
  轨迹。
- MPC 输入的第一个点始终是当前底盘位置。
- 单帧无效、倒退或明显断裂的候选不能污染历史状态。
- 管理器更新为线性复杂度，不能再次阻塞规划线程。

## 方案比较

### 方案 A：近场历史缓存加可替换远场，采用

管理器区分稳定的 `near_history` 与可替换的 `far_candidate`。旧远场点随车辆
接近而进入 `1.0 m` 窗口时成为近场历史；合格的新候选只替换远场。最终把
底盘、近场历史和远场候选拼成 MPC 引导折线。

该方案保留 D435 当前看不到的近场信息，同时让远场及时响应模型输出。

### 方案 B：固定承诺区间加连续重叠

近场稳定，但对第一条轨迹依赖很强，而且当前逐点投影实现开销过大，因此
移除。

### 方案 C：多帧点云融合

可以进一步降低观测噪声，但需要数据关联、置信度和分支切换策略。当前 MPC
已经通过软代价和车辆动力学生成可执行轨迹，本次不增加这层复杂度。

## 状态与更新流程

`TrajectoryManager` 在 odom 坐标系中维护：

- `near_history`：当前底盘前方、沿路径弧长不超过 `1.0 m` 的旧引导点；
- `far_candidate`：最近一次接纳的远场候选点，用于当前 MPC 参考，也用于在
  车辆前进后向 `near_history` 提供旧观测。

每次更新按以下顺序执行：

1. 用当前底盘位置在上一轮完整参考折线上找最近前向投影，删除已经驶过的
   部分。
2. 从旧参考剩余部分中截取前方 `1.0 m`，作为本轮 `near_history`。距离按
   折线弧长计算，不按到底盘的欧氏半径计算。
3. 对新候选做有限、线性复杂度的门控。候选必须有限、至少包含两个不同点；
   近场末段到候选首段的连接距离和方向变化分别不得超过既有
   `join_distance` / `join_heading` 限制。该检查只计算接缝，不把候选逐点
   投影到历史轨迹。
4. 新候选合格时，直接替换 `far_candidate`；不搜索重叠区，也不修改
   `near_history`。候选不合格或本轮没有候选时，继续使用尚未驶过的旧远场。
5. 临时在新候选前加入底盘位置并计算候选自身的累计弧长，去掉累计弧长小于
   `1.0 m` 的新候选点，避免最新观测覆盖历史近场；边界上的插值点保留为
   远场起点。
6. 依次拼接当前底盘位置、`near_history` 和 `far_candidate`，删除连续重复
   点，并按弧长以默认 `0.05 m` 间隔重采样后交给 MPC。

上述拼接不设置 `0.8–1.2 m` 融合区，不对接缝两侧做加权或样条混合。MPC
继续把参考位姿作为软代价，并通过现有车辆动力学、速度和角速度限制求解。

## 启动和失效行为

启动时还没有历史引导点。首次合格候选到来后，从当前底盘位置连接到候选首
点，作为临时近场参考。这段空间没有相机观测，无法凭空恢复真实引导点；随着
车辆前进，先前候选的真实点进入 `1.0 m` 窗口后会逐步取代启动连接段。

候选请求失败、critic 不足或几何门控失败时，不清空已有近场与远场。只有旧
参考确实耗尽，且没有合格候选可用时，才返回无轨迹并触发现有安全停车逻辑。

历史窗口长度新增为命令行参数：

```text
--trajectory-history-distance 1.0
```

删除不再参与算法的承诺区间和连续重叠参数，保留点间距、最短剩余距离、接缝
距离和接缝方向参数。

## 诊断和可视化

计划日志记录：

- `history_length_m` 和 `history_point_count`；
- 新候选是否接纳及拒绝原因；
- 远场候选剩余长度；
- 交给 MPC 的完整参考轨迹；
- TrajectoryManager 单次更新时间。

BEV 中黄色离散点表示完整 MPC 引导折线；近场历史可以保留独立颜色或字段，
便于确认 `1.0 m` 窗口随底盘前移。现有使用帧同步 odom 位姿进行投影的修复
保持不变。

## 测试

单元测试覆盖：

- 历史点只保留当前底盘前方 `1.0 m` 弧长；
- 底盘后方点及时删除；
- 旧远场点随车辆前进进入近场历史；
- 合格新候选替换远场但不改变近场历史；
- 不需要 `0.5 m` 连续重叠即可更新远场；
- 非有限、过大间断和过大方向突变候选被拒绝；
- 候选缺失时继续执行未耗尽的旧参考；
- 启动时从精确底盘位置连接首个候选；
- MPC 输入始终从当前底盘位置开始；
- 典型约 70 点历史与 70 点候选的更新耗时保持在适合实时规划的数量级，并
  且不再出现多层逐点投影扫描。
