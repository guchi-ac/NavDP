# 动态盲区引导点 TrajectoryManager 设计

## 背景

D435 当前视角下，diffusion 输出的第一个有效引导点通常距离底盘约 `1 m`。
如果直接把这些点交给 MPC，底盘与首点之间没有引导信息。之前实现的固定
`1.0 m` 历史窗口能够补近场，但把传感器现象误写成了固定轨迹边界：首点距离
变化时仍精确截取 `1.0 m` 没有必要。

本设计把“当前 diffusion 首点”视为可见区域的动态起点。TrajectoryManager
只用旧引导路径补齐底盘到这个起点之间的盲区，不承诺固定距离。

## 目标

- MPC 参考轨迹始终从当前底盘位置开始。
- 历史引导点只用于补齐底盘与当前 diffusion 首点之间的盲区。
- 历史保留长度由当前首点在旧路径上的投影动态决定，通常约 `1 m`，但不硬
  编码为 `1 m`。
- 当前首点之后全部采用最新合格 diffusion 候选。
- 不使用固定承诺区间、连续重叠、融合区或数值平滑。
- 单帧无效、低 critic 或接缝明显不连续时继续执行尚未耗尽的旧路径。
- 每次更新只进行一次候选首点到历史折线的投影，保持线性复杂度。
- `Mpc_controller` 的参数 `N` 表示当前 diffusion 对应的预测步数，不包含
  额外补出的盲区步数。
- MPC 实际预测长度为 `N_total = K_blind + N`，其中 `K_blind` 是本轮盲区
  引导点对应的附加步数。
- `ref_gap`、`desired_v * ref_gap * T` 距离采样和现有稀疏跟踪代价保持原
  逻辑，只把采样来源改成“盲区点 + 全部 diffusion 点”。

## 方案比较

### 方案 A：候选首点动态投影，采用

将当前 diffusion 首点投影到已经前推的旧路径。保留底盘到投影点的旧路径，
再接入当前首点及其后全部候选点。它直接对应“历史补盲区”的需求，并允许首点
距离随相机视角和场景变化。

### 方案 B：固定 `1.0 m` 历史窗口

实现简单，但会在首点距离不是 `1.0 m` 时保留过多或过少历史，还引入没有
业务含义的精确弧长边界，因此移除。

### 方案 C：历史与当前候选融合

需要点对应和权重设计，也会修改 diffusion 已经给出的远场路径。本次由 MPC
负责可执行轨迹平滑，不增加融合层。

## MPC 预测长度方案

### 方案 A：仅在有效总长度变化时重建求解器，采用

`Mpc_controller` 接收 diffusion 预测步数 `N` 和附加盲区步数 `K_blind`，
内部使用 `N_total = K_blind + N` 创建状态和控制变量。同一
`N_total` 下只调用 `update_ref_traj()`；总长度变化时才重建控制器。

本机只读基准中，`N_total=10/20/30` 的控制器构造约为
`12/22/31 ms`，首次求解约为 `52/42/59 ms`，低于当前 `0.3 s` 规划周期。
该方案直接满足预测长度语义，且不引入求解器缓存和固定最大盲区参数。

### 方案 B：缓存不同长度的求解器

可避免重复构造，但会长期保存多个 CasADi/Ipopt 对象，并复用较旧的 warm
start。本次没有证据需要这层缓存，因此不采用。

### 方案 C：预分配最大预测长度并使用掩码

避免动态构造，但需要新增最大盲区长度、有效步掩码和尾部控制约束；优化器每
次仍承担最大维度开销，也不再直观对应 `K_blind + N`，因此不采用。

## 状态与数据流

`TrajectoryManager` 在 odom 坐标系中保存上一轮可执行的完整参考折线
`active_traj`。每轮输入：

- 当前底盘二维位置；
- 可选的当前 diffusion 候选折线；
- 候选是否通过 critic 门控。

更新流程：

1. 将底盘投影到旧 `active_traj`，删除已经驶过的部分，并以精确底盘位置作为
   剩余折线起点。
2. 没有合格新候选时，继续执行这条前推后的旧路径。
3. 有合格候选时，取候选第一个引导点 `candidate[0]`，将它投影到前推后的旧
   路径，得到历史接缝点和从底盘到接缝点的历史弧长。
4. 只保留底盘到该接缝点之间的旧引导折线。这一段就是本轮动态盲区历史。
5. 检查接缝点到 `candidate[0]` 的距离，以及历史末段、连接段和候选首段之间
   的方向变化。分别沿用 `join_distance` 和 `join_heading` 门限。
6. 接缝合格时，按默认 `0.05 m` 间隔补齐历史盲区，再依次拼接接缝点和当前
   候选全部原始引导点。只删除连续重复点，不对 diffusion 候选做截断或整体
   重采样。
7. 接缝不合格时，不部分更新状态，继续执行前推后的旧路径。

候选首点之后的旧路径全部丢弃。因此历史不会继续影响当前 diffusion 已经可见
的远场区域。算法不搜索连续重叠，也不在多个接缝中选择最远点。

TrajectoryManager 同时返回：

- `blind_point_count`：拼接参考中底盘之后、diffusion 首点之前的盲区引导点
  数量；
- `diffusion_point_count`：当前接纳并保留的 diffusion 引导点数量；
- `mpc_prediction_steps = blind_point_count + diffusion_point_count`。

候选被拒绝或缺失时，上述 diffusion 元数据随保留的旧路径一起保留，不能用
失败候选覆盖。

## MPC 参考与 `ref_gap`

TrajectoryManager 返回的 `active_traj` 按顺序包含：

```text
底盘锚点 + 动态盲区历史点 + 当前 diffusion 的全部引导点
```

其中首个底盘锚点同时作为 `opt_states[0]`，不计入 `N` 或 `K_blind`。参与
预测长度计数的参考序列是锚点之后的“盲区点 + 全部 diffusion 点”。
`Mpc_controller` 的公开 `N` 保持 diffusion 预测步数语义，内部状态和控制
变量按 `N_total` 创建。

`make_ref_denser()` 和 `find_reference_traj()` 保持原算法：

1. 加密完整组合折线；
2. 从当前底盘的最近路径点开始；
3. 使用 `desired_v * ref_gap * T` 作为相邻参考位姿的目标弧长；
4. 每隔 `ref_gap` 个预测步加入一次参考位姿代价；
5. 参考不足时继续使用组合折线终点。

因此 `ref_gap` 不改成按引导点索引抽样，也不要求每个原始引导点都进入目标
函数；“全部 diffusion 点”表示它们完整保留在被加密和距离采样的源折线中。

## 启动和耗尽

首次没有旧路径时，只对当前底盘位置到候选首点之间的连接段按
`point_spacing` 补点，再原样追加全部 diffusion 引导点。连接段上的点计入
`K_blind`；MPC 从真实底盘状态求解，不要求机器人精确穿过插值点。

候选缺失、critic 不足或几何无效时保留旧路径。只有旧路径剩余弧长小于
`min_remaining`，并且没有可初始化的新候选时，才返回无轨迹并触发现有安全
停车逻辑。

## 参数与诊断

保留：

```text
--trajectory-point-spacing 0.05
--trajectory-join-distance 0.50
--trajectory-join-heading-deg 60.0
--trajectory-min-remaining 0.20
```

不再提供固定历史距离、承诺区间或连续重叠参数。

每条计划诊断记录：

- 新候选是否接纳及原因；
- 候选首点到历史投影接缝的距离；
- 实际保留的盲区历史弧长和点数；
- 当前候选远场长度；
- 盲区点数、diffusion 点数和 `N_total`；
- 最终 MPC 参考折线；
- TrajectoryManager 更新时间。

BEV 黄色引导点继续表示最终 MPC 参考折线，并继续使用 RGB-D 帧同步的 odom
位姿投影。

## 测试

单元测试覆盖：

- diffusion 首点位于 `0.7 m` 时只保留约 `0.7 m` 动态历史；
- diffusion 首点位于 `1.3 m` 时可保留约 `1.3 m` 动态历史，证明没有固定
  `1.0 m` 截断；
- 曲线路径中保留到候选首点的最近历史投影；
- 当前候选从首点开始替换全部远场，不要求连续重叠；
- 候选接缝距离或方向超限时旧路径保持不变；
- 低 critic、无效候选、旧路径耗尽和首次初始化；
- 首次初始化只补点盲区连接段，不丢失或整体重采样 diffusion 点；
- 每条输出从当前底盘位置开始，返回值不可修改内部状态；
- 典型 70 点路径更新低于宽松的 `0.2 s` 性能回归上限。

MPC 和客户端测试覆盖：

- `N` 只记录 diffusion 预测步数；
- `K_blind=0` 时实际预测长度等于 `N`；
- `K_blind>0` 时状态、控制和参考数量按 `K_blind + N` 创建；
- `find_reference_traj()` 仍使用原来的距离采样和 `ref_gap`；
- 总长度不变时只更新参考，总长度变化时重建控制器；
- 参数移除、动态盲区诊断、MPC 安装轨迹和 BEV 轨迹来源。
