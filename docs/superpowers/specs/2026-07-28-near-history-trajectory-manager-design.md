# 动态盲区引导点 TrajectoryManager 设计

## 背景

D435 当前视角下，diffusion 输出的第一个有效引导点通常距离底盘约 `1 m`。
如果直接把这些点交给 MPC，底盘与首点之间没有引导信息。之前实现的固定
`1.0 m` 历史窗口能够补近场，但把传感器现象误写成了固定轨迹边界：首点距离
变化时仍精确截取 `1.0 m` 没有必要。

本设计把“当前 diffusion 首点”视为可见区域的动态起点。TrajectoryManager
只用旧引导路径补齐底盘到这个起点之间的盲区，不承诺固定距离。

## 目标

- MPC 参考轨迹始终从当前底盘位置开始。
- 历史引导点只用于补齐底盘与当前 diffusion 首点之间的盲区。
- 历史保留长度由当前首点在旧路径上的投影动态决定，通常约 `1 m`，但不硬
  编码为 `1 m`。
- 当前首点之后全部采用最新合格 diffusion 候选。
- 不使用固定承诺区间、连续重叠、融合区或数值平滑。
- 单帧无效、低 critic 或接缝明显不连续时继续执行尚未耗尽的旧路径。
- 每次更新只进行一次候选首点到历史折线的投影，保持线性复杂度。

## 方案比较

### 方案 A：候选首点动态投影，采用

将当前 diffusion 首点投影到已经前推的旧路径。保留底盘到投影点的旧路径，
再接入当前首点及其后全部候选点。它直接对应“历史补盲区”的需求，并允许首点
距离随相机视角和场景变化。

### 方案 B：固定 `1.0 m` 历史窗口

实现简单，但会在首点距离不是 `1.0 m` 时保留过多或过少历史，还引入没有
业务含义的精确弧长边界，因此移除。

### 方案 C：历史与当前候选融合

需要点对应和权重设计，也会修改 diffusion 已经给出的远场路径。本次由 MPC
负责可执行轨迹平滑，不增加融合层。

## 状态与数据流

`TrajectoryManager` 在 odom 坐标系中保存上一轮可执行的完整参考折线
`active_traj`。每轮输入：

- 当前底盘二维位置；
- 可选的当前 diffusion 候选折线；
- 候选是否通过 critic 门控。

更新流程：

1. 将底盘投影到旧 `active_traj`，删除已经驶过的部分，并以精确底盘位置作为
   剩余折线起点。
2. 没有合格新候选时，继续执行这条前推后的旧路径。
3. 有合格候选时，取候选第一个引导点 `candidate[0]`，将它投影到前推后的旧
   路径，得到历史接缝点和从底盘到接缝点的历史弧长。
4. 只保留底盘到该接缝点之间的旧引导折线。这一段就是本轮动态盲区历史。
5. 检查接缝点到 `candidate[0]` 的距离，以及历史末段、连接段和候选首段之间
   的方向变化。分别沿用 `join_distance` 和 `join_heading` 门限。
6. 接缝合格时，依次拼接历史盲区、接缝点、当前候选全部引导点，删除连续
   重复点，并按弧长以默认 `0.05 m` 间隔重采样后交给 MPC。
7. 接缝不合格时，不部分更新状态，继续执行前推后的旧路径。

候选首点之后的旧路径全部丢弃。因此历史不会继续影响当前 diffusion 已经可见
的远场区域。算法不搜索连续重叠，也不在多个接缝中选择最远点。

## 启动和耗尽

首次没有旧路径时，将当前底盘位置和首个合格候选直接组成参考折线并重采样。
底盘到候选首点之间是启动时唯一可构造的临时参考；MPC 从真实底盘状态求解，
不要求机器人精确穿过插值点。

候选缺失、critic 不足或几何无效时保留旧路径。只有旧路径剩余弧长小于
`min_remaining`，并且没有可初始化的新候选时，才返回无轨迹并触发现有安全
停车逻辑。

## 参数与诊断

保留：

```text
--trajectory-point-spacing 0.05
--trajectory-join-distance 0.50
--trajectory-join-heading-deg 60.0
--trajectory-min-remaining 0.20
```

不再提供固定历史距离、承诺区间或连续重叠参数。

每条计划诊断记录：

- 新候选是否接纳及原因；
- 候选首点到历史投影接缝的距离；
- 实际保留的盲区历史弧长和点数；
- 当前候选远场长度；
- 最终 MPC 参考折线；
- TrajectoryManager 更新时间。

BEV 黄色引导点继续表示最终 MPC 参考折线，并继续使用 RGB-D 帧同步的 odom
位姿投影。

## 测试

单元测试覆盖：

- diffusion 首点位于 `0.7 m` 时只保留约 `0.7 m` 动态历史；
- diffusion 首点位于 `1.3 m` 时可保留约 `1.3 m` 动态历史，证明没有固定
  `1.0 m` 截断；
- 曲线路径中保留到候选首点的最近历史投影；
- 当前候选从首点开始替换全部远场，不要求连续重叠；
- 候选接缝距离或方向超限时旧路径保持不变；
- 低 critic、无效候选、旧路径耗尽和首次初始化；
- 每条输出从当前底盘位置开始，返回值不可修改内部状态；
- 典型 70 点路径更新低于宽松的 `0.2 s` 性能回归上限。

客户端测试覆盖参数移除、动态盲区诊断、MPC 安装轨迹和 BEV 轨迹来源。最终
运行 Git 跟踪测试、Python 编译、最新日志离线回放和 `git diff --check`。
